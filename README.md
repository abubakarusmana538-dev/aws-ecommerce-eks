# Usman Abubakar E-commerce Project: AWS Infrastructure (Terraform)

Modular, multi-environment Terraform for an e-commerce platform on AWS:
VPC, EC2, EKS, RDS and S3. Dev and prod use the same modules with different settings.

## Architecture

```
                         Internet
                            |
                    [ Internet Gateway ]
                            |
 +--------------------- VPC (10.x.0.0/16) ----------------------------+
 |                                                                      |
 |  PUBLIC subnets (2 AZs)        Load balancers, NAT Gateway(s)        |
 |        |                                                             |
 |        v  (outbound only, via NAT)                                   |
 |  PRIVATE subnets (2 AZs)       EKS worker nodes, EC2 app server      |
 |        |                                                             |
 |        v  (port 5432, security-group rules only)                     |
 |  DB subnets (2 AZs)            RDS PostgreSQL, NO internet route     |
 |                                                                      |
 |  S3 Gateway Endpoint: private/db route tables -> S3 (no NAT cost)    |
 +----------------------------------------------------------------------+

  S3 bucket (private, versioned, encrypted)   Secrets Manager (DB password)
```

## Layout

```
aws-ecommerce-terraform/
├── modules/                 reusable building blocks
│   ├── vpc/                 VPC, subnets, IGW, NAT, route tables, S3 endpoint
│   ├── s3/                  private, versioned, encrypted bucket
│   ├── ec2/                 private app server (SSM access, no SSH)
│   ├── eks/                 EKS control plane + managed node group
│   └── rds/                 PostgreSQL in isolated subnets
├── environments/
│   ├── dev/                 cheap: 1 NAT, small nodes, single-AZ DB
│   └── prod/                hardened: NAT per AZ, Multi-AZ DB, deletion protection
├── k8s/web.yaml             sample "Usman Abubakar E-commerce Project" web page
└── .github/workflows/       CI: terraform validate on every push
```

## Dev vs prod

| Setting | dev | prod |
|---|---|---|
| VPC CIDR | 10.0.0.0/16 | 10.1.0.0/16 |
| NAT Gateways | 1 (shared) | 1 per AZ |
| EKS nodes | 2 x t3.small | 3 x t3.medium (2 to 6) |
| RDS | db.t3.micro, single-AZ, 1-day backups | db.t3.small, Multi-AZ, 7-day backups |
| RDS deletion protection / final snapshot | off / skipped | on / taken |
| S3 force destroy | yes | no |

## Deploy

Prerequisites: Terraform 1.5 or newer, AWS CLI configured (`aws configure`), kubectl.

```bash
cd environments/dev
terraform init
terraform plan
terraform apply          # EKS + RDS take about 15-20 minutes

aws eks update-kubeconfig --region eu-west-2 --name ecommerce-dev-eks
kubectl get nodes
kubectl apply -f ../../k8s/web.yaml
kubectl get svc web -n ecommerce      # open the EXTERNAL-IP in a browser (http://)
```

Production is the same with `cd environments/prod`.

## Clean up (order matters)

```bash
kubectl delete -f k8s/web.yaml        # removes the load balancer Kubernetes created
cd environments/dev
terraform destroy
```

If you skip the first step, `terraform destroy` can hang on the VPC because the
load balancer still uses its subnets.

## Notes

- **Cost:** EKS, NAT Gateways, RDS and the nodes bill hourly. Destroy when not in use.
- **Free-tier accounts:** RDS backup retention is capped at 1 day and only free-tier
  instance types can launch. Dev defaults already fit; prod will not launch on a free-tier plan.
- **Database password:** generated by AWS and stored in Secrets Manager
  (see the `rds_secret_arn` output). It is never written to Terraform files.
- **Remote state:** local by default. Uncomment `backend.tf` in each environment once you
  have an S3 bucket and DynamoDB lock table.
- **Never commit** `*.tfstate`, `*.tfvars` or `*.pem` files. `.gitignore` already excludes them.
- Run `terraform fmt -recursive` before committing.
